## A. Input and focus

1. **A client's popup keeps the keyboard when the focus goes elsewhere.** Only
   `view_focus()` ends a popup's keyboard grab (`wlr_seat_pointer_end_grab`,
   src/view.c). `focus_next()` with nobody left (src/view.c), `iconbox_focus()`
   (src/iconbox.c) and `give_keyboard()` for a layer surface (src/layer.c) clear or
   move the focus, which an xdg popup grab ignores. Firefox with its menu open,
   Alt+F9: keys go to the invisible menu. Alt+Tab to the icon box: the same. An
   exclusive layer surface mapping while a menu is open gets no keys.
   Fix: end the grab there too, unless a drag is on.

2. **A click on a panel takes the keyboard from the icon box, and nobody gets it.**
   `handle_press()` (src/input.c) blurs the box before `layer_handle_click()`, also
   for a surface without keyboard interactivity (waybar's clock).
   Fix: blur only when the layer surface really took the keyboard.

3. **A frame button's broken-off press.** `clear_grab()` resets the cursor mode but
   not `view->pressed`/`pressed_inside`: after a desktop switch or a remap during
   the press, the button stays drawn sunken. And `handle_button_release()` doesn't
   update the pointer focus (the icon box branch does).

4. **A virtual pointer's output is ignored** (`on_new_virtual_pointer`, src/input.c).
   wayrdp creates its pointer for one output; absolute motion is in that output's
   coordinates, but mwc maps it over the whole layout. Two monitors: clicks land
   wrong. Fix: `wlr_cursor_map_input_to_output()` with `suggested_output`.

5. **An exclusive top layer surface takes the keyboard from an exclusive overlay one**
   (`update_keyboard()`, src/layer.c). layer-shell: the seat gives the keyboard "to
   the top-most layer which has keyboard interactivity set to exclusive".

6. **Keys mwc handles itself don't repeat** (`grab_key`, `menu_key`, `iconbox_key`):
   wlroots doesn't repeat for the compositor. Holding an arrow during Alt+F7, in a
   menu or in the icon box moves once.

## B. Hostile clients

7. **A layer surface can take the keyboard back at will.** `update_keyboard()` gives
   a top or overlay surface with on-demand interactivity the keyboard on map and on
   every commit that turns it on again: a 1x1 surface flipping none/on-demand pulls
   the keyboard away while the user types.
   Fix: on-demand gets it on map at most, then only by a click.

8. **X11 programs act on others' windows.** `xw_request_activate` and
   `xw_request_minimize` (src/xwayland.c) follow `_NET_ACTIVE_WINDOW` and
   `WM_CHANGE_STATE` from any X client: focus theft from Wayland windows, restoring
   what the user minimized. `um_map` gives an override-redirect window the keyboard
   when it appears, also while a Wayland window has it.
   Fix: honour them when the focused window is an X11 window of the same program,
   or nothing has the focus; otherwise mark the window for attention.

9. **The fifo queue has no bound** (src/fifo.c): a client looping set_barrier,
   wait_barrier, commit makes mwc hold a surface state per commit, without limit.
   Fix: cap held commits per surface; past it, clear the barrier early.

10. **Many windows freeze mwc.** `view_parent()` (src/hints.c) scans all views and is
    called per view in `views_update_layers()` and `view_raise()`: one X11 client
    mapping thousands of small windows, chained by WM_TRANSIENT_FOR, makes every
    focus change O(16 n²). Fix: the parent through `xsurface->parent->data` or
    `toplevel->parent->base->data`. Also review 2026-11-14 point 12.

11. **Floods and limits.**
    - ext-workspace switches (src/workspace.c) have no rate limit and can give the
      requesting client the focus.
    - A layer exclusive zone may leave 1 px usable (X11 struts keep `MIN_ROOM`), and
      toggling it reconfigures every maximized and snapped window per commit.
    - app_id or WM_CLASS set to the same value again costs a theme change and a
      tiling round.

12. **Other abuse.**
    - An idle inhibitor counts with a surface that was never mapped (src/main.c).
    - Move/resize requests aren't tied to the window under the pointer: the xdg
      serial is checked against no origin, X11 only checks that a button is down.
    - With `outputManagement: true`, a client can switch off every monitor.

## C. Protocol correctness

13. **Fullscreen smaller than the output, or translucent.** Placed at the top left,
    no backdrop (src/view.c, `frame_fill` off without a frame). xdg-shell: "the
    compositor will position the surface in the center of the output and compensate
    with border fill"; other content "must" not show under a non-opaque one.

14. **X11 sticky, shaded, demands attention.** wlroots advertises them and writes a
    client's request into `_NET_WM_STATE`; mwc has no handlers, and its own Shade and
    "On All Desktops" aren't published.

15. **X11 stacking on lower.** `view_lower_one()` doesn't restack the X window, so
    `_NET_CLIENT_LIST_STACKING` and the X server's order go stale after Lower and
    Alt+Shift+Tab.

16. **Smaller points.**
    - `set_fullscreen`'s output preference is ignored.
    - wm_capabilities always offer maximize, also to dialogs mwc won't maximize.
    - Popups are constrained to the output under the window's top left corner.
    - Several keyboards don't share modifiers (no `wlr_keyboard_group`).
    - No pointer constraints, relative pointer or shortcuts inhibit.
