# Review 2026-11-14

Four reviewers, each on one topic, read all of `src/` at bbb5d6e (with the icon box):
memory management, performance and hot paths, clean style without hacks, crash safety.
None found a crash, a use-after-free or a leak a client or user can trigger. The points

## A. Icon box bugs

Done in 76934cd (branch fix/iconbox-review).

1. **The chosen icon stays highlighted after a desktop switch.** `desktop_switch()`
   (src/desktop.c:110) sets `server->desktop = n` before `iconbox_desktop_changed()`.
   `set_focused(false)` then looks up `cur()->sel` of the new desktop in the old
   desktop's `ib.icons`: the wrong icon is redrawn, and the old desktop's chosen icon
   keeps its highlighted label, which shows again on the way back.
   Fix: call `iconbox_desktop_changed()` before changing `server->desktop`.

2. **Alt+Tab can skip the box or reach it too early.** A tab switch (src/tabs.c:149)
   moves `to` into `from`'s place in `server->views` but leaves `to->raise_seq` as it
   was; when the group isn't focused, nothing calls `view_raise_one()`.
   `iconbox_cycle_takes()` then compares against the wrong number.
   Fix: `to->raise_seq = from->raise_seq;` next to the `wl_list_insert`, as `pass_icon()`
   does for `icon_seq`; in mwc.h, note that `raise_seq` changes together with the list.

3. **Nobody has the keyboard when the box loses its last icon.** The box has the
   keyboard (`iconbox_focus()` deactivated the window and cleared the seat); the only
   minimized program quits, or its window is sent to another desktop.
   `iconbox_arrange()` blurs the box, but `was_active` (src/view.c, unmap) and `lost`
   (src/desktop.c, `view_set_desktop`) are false, so no window gets the focus until
   the next click.
   Fix: when `iconbox_arrange()` blurs the box because it is empty, `view_focus_top()`
   if no window has the focus.

4. **A held box button outlives a desktop switch or a grab.** `ib.pressed`
   (src/iconbox.c, `iconbox_press`/`iconbox_release`) is only cleared by a release
   that reaches `iconbox_release()`. If an ext-workspace client switches the desktop
   while minimize is held, the release minimizes the new desktop's box; if a menu or a
   client's move starts first, the release goes elsewhere and the button stays drawn
   pressed. Keys also still act while a box button is held (the `CURSOR_BUTTON` guard
   in `handle_keybinding()` doesn't apply).
   Fix: use `CURSOR_BUTTON` for the box's buttons too, so one release path serves
   both; at least reset `ib.pressed` in `iconbox_desktop_changed()` and `hide_all()`.

5. **Vertical box with a large font.** Its width is fixed at 2B+2P+ICON_W (86 px), the
   horizontal one has a floor of `2*B + 3*T`. With a title height T ≥ 40 the title's
   width is ≤ 0 and the buttons move past the left edge: the title can't be hit
   (no double-click maximize), minimize is only half reachable.
   Fix: the same floor for the vertical box (src/iconbox.c, `iconbox_arrange()`).

6. **`ib.icons` keeps freed views once the box is switched off** (latent).
   `icons_arrange()` no longer calls `iconbox_arrange()`, so the array isn't rebuilt;
   a window that was an icon in it can be closed and freed. Every reader is gated by
   `ib.shown`/`ib.focused` today; one ungated reader would make it a use-after-free.
   Fix: free and clear it in `hide_all()`.

## B. Performance

7–11 done on branch refactor/hot-paths; 12 left as is (a shortcut in
`view_raise()` would rely on list order = scene and X11 stacking).

7. **Every tiling round reconfigures and redraws every tiled window.**
   `view_apply_tile()` (src/view.c:672) always calls `view_set_geometry()` (a configure
   for xdg, a ConfigureNotify for X11) and `frame_render()` (4 buffers, a Pango title),
   for each tiled window on each `tile_arrange()`: every map and unmap (also of floating
   dialogs), minimize, restore, desktop switch, tab change, and every commit that
   changes a window's size limits. A client whose minimum size depends on its width
   triggers the next round from its own commit.
   Fix: skip `view_set_geometry()` when place and requested size are the same; render
   only when size, shaded state or `tile_main` changed.

8. **The move/resize feedback box measures its text on every motion event.**
   `feedback_show()` (src/outline.c:144) calls `text_size()` (a cairo surface, a Pango
   layout, a parsed font) before checking whether the text changed. During a move the
   text changes on each event: then also a new buffer and `draw_text()`. At 1000 Hz,
   a thousand layouts and uploads per second, of which 60–144 are seen.
   Fix: compare first, measure only on change; or render once per frame.

9. **A title change redraws all four frame strips.** `view_update_title()`
   (src/view.c:867), from xdg and X11 title changes: no check whether the title
   changed, also for hidden and minimized windows, and `icon_render()` even when the
   label is the app_id. A program setting its title per line of output costs a Pango
   layout and 4 buffers each time.
   Fix: skip unchanged titles and hidden windows, redraw only the top strip.

10. **The font string is parsed for every text drawn.**
    `pango_font_description_from_string(theme.font)` in `draw_text()` (src/frame.c),
    `text_size()` (src/outline.c), `text_width()` (src/iconbox.c), src/menu.c.
    Fix: parse once in `theme_init()`, keep the description in `theme`.

11. **Opaque resize sends a configure per motion event** without waiting for the
    client's ack (`resize_to()` in src/input.c). Only with `moveOpaque: true`.
    Fix: while a configure is outstanding, keep only the latest size and send it on
    the client's commit.

12. **Focus changes are O(n²) in the number of windows.** `views_update_layers()` calls
    `view_transient_root()` for every view, twice per focus change; `view_raise()` scans
    for transients on every click into a client, even an already focused one. Only
    matters from about 100 windows.

## C. Robustness

13 and 14 done on branch fix/alloc-checks.

13. **Unchecked allocations** crash on a NULL pointer when memory runs out:
    src/xwayland.c:477, 632; src/view.c:292, 1030, 1656, 1724, 1812, 1890, 1942;
    src/tile.c:115, 456; src/tabs.c:299; src/layer.c:379; src/main.c:282, 479;
    src/input.c:1345; src/config.c: `realloc` at 112 and 147 (also loses the old block),
    `strdup` at 115–116, 148, 168, 182, 247 (247: `strtok_r` with a NULL save pointer,
    168: `strchr(NULL)`). fifo.c, workspace.c, draw.c, shmalloc.c and iconbox.c check.
    Fix: check and fail cleanly (`wl_client_post_no_memory` for protocol objects), or
    one `xcalloc` that logs and aborts.

14. **Nits.** src/shmalloc.c error paths free a buffer after `wlr_buffer_init()`
    without `wlr_buffer_finish()` (harmless, nothing attached yet). src/config.c:413
    `static const char *warned` points into rules a reload frees: at worst one lost
    "not a boolean" log line.

## D. Style in the icon box

Done in 76934cd (branch fix/iconbox-review).

15. **Duplicated code.**
    - `by_icon_seq` and the "minimized, on this desktop, by `icon_seq`" collection exist
      in src/frame.c and src/iconbox.c: one `icons_in_order()` helper.
    - The `~/` expansion is copied from src/wallpaper.c without its comment: one
      `expand_home()` helper.
    - The box's minimize/maximize buttons redraw `draw_button()` from src/frame.c by
      hand, with the same glyph sizes (`5`, `T * 11 / 20`): one shared function, so the
      two can't drift apart.

16. **Constructs that read like hacks.**
    - `ib.seq = LONG_MIN / 2` in `iconbox_init()`: unexplained; `iconbox_lowered()`
      says the same in the model's own terms.
    - `static int acc` in `iconbox_wheel()`: hidden state across calls, never reset,
      and the same loop as `tab_wheel` in src/input.c. Keep it in `ib`, share a
      `wheel_steps()` helper.
    - The forward declaration of `load_logo_file()`, which also fills `ib.logo_image`
      as a side effect: a `read_logo()` that returns the surface, defined first.
    - The icon margin 8, its 16, and `tight ? 0 : 8` as bare numbers in src/frame.c and
      src/iconbox.c: `ICON_MARGIN` and an `icon_gap()` next to `ICON_W` in mwc.h.
    - `if (iconbox_enabled()) break;` inside the loop in `plan()` (src/tile.c): either
      the box or the loose icons, decided once before the loop.

17. **Repeated work.**
    - `iconbox_enabled()` parses the config on every call (`icon_render`, clicks,
      wheel, once per view in `plan()`): keep it in `ib`, set on load and reload.
    - `text_width()` builds a surface and a layout per chrome render only to hide
      "Icons" when it doesn't fit; `draw_text()` already ellipsizes, as window titles
      do. Delete it.
    - `iconbox_arrange()` renders the logo and the chrome on every call; the logo
      could be rendered once per load and theme.
    - The 256 px logo is decoded on every reload, even with the box off.

18. **Interface.**
    - `iconbox_focusable()` is only used inside iconbox.c: static.
    - Several functions take a `server` they ignore (they use `ib.server`), while
      `iconbox_enabled()` takes none: one convention, the unused parameters dropped.
    - `draw_arrow(…, int dir, …)` with 0–3: an enum or two bools, like `draw_mark()`.

19. **Test.** `sleep 0.6` in tests/iconbox.sh only dodges the double-click interval.
    Clicking an icon instead of the title bar focuses the box without waiting and also
    tests click-to-select.
