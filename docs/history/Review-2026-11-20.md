# Review 2026-11-20

Three reviewers on refactor/no-xwayland at 9474172, one lens each: what the removal of Xwayland left behind in src/ and the build, behaviour changes for xdg and layer clients, the ported tests and tests/xdgc. No verifier; the points below were checked against the code. 13 points, all settled: first 6 fixed and 7 left, then the 7 taken up as well. ## Status

All points settled on refactor/no-xwayland. Each fix with a test that fails without it, checked by taking the change out, except where the point says otherwise.

1. **A tab shown after the layout moved its group is drawn where it was hidden** `src/tabs.c:154`, tabs, medium. Already on main.

   Tiling is on and a group is in the layout. The layout moves the group, here two new windows pushing it down the stack; the hidden tab is sized for the new cell (tabs_sync_sizes()) but its scene node stays where it was hidden. Switching to it, move_place() gives it the group's x and y, and view_apply_tile() finds it at the size and place it was asked for, so it sends nothing and moves nothing: the tab is drawn at the old cell, and clicks there go by view->x. Review 2026-11-19b T-7 refuted this with a case where the old and the new place happened to be the same.

   [Fixed: switch_to() puts the node of the tab it shows at its place. tabs.sh: two newcomers move a group, the other tab is drawn in the group's cell.]

2. **Four test targets don't build a tool their script needs** `Makefile:394`, build, medium.

   snap-test and tile-test lacked build/layerc, session-test and outputs-test build/xdgc; make test passed only because earlier targets built them. desktop-test and misc-test listed tools their scripts no longer use. tabs.sh didn't check for pngtool, session.sh not for idlec.

   [Fixed. No test: a make target.]

3. **xdgc acks a configure of the mapping it just left** `tests/xdgc.c:791`, tests, medium.

   After the null buffer, a configure mwc sent before it saw the unmap still arrives. wlroots has dropped it with the surface's reset, so the ack is a wrong serial, and the buffer drawn with it one for an unconfigured surface: the client is killed. The drag before window.sh's gplain sends none, so it didn't show.

   [Fixed: a hidden window takes no configure until it starts over. No test: a race.]

4. **Code that only X11 reached** `src/view.c:1512`, leftovers, low.

   input_button_held() and layer_keyboard_back() had no callers. view_handle_map() was only called with focus, so its other branch, tabs_bring_instead() and switch_to()'s instead were dead, as was view_set_fullscreen_asked() and its focus. own_layer() can't return less than VL_NORMAL any more, view_update_properties() raised layers for a window type nothing reads, and begin_interactive() and the window menu read the size limits again, which xdg_commit() does on every commit. badclient's paste modes had no test left.

   [Removed. view_focus()'s branch for a window it can't focus stays: a tab that can't come to the front is still hidden there. No test: code taken out.]

5. **Comments and docs that still spoke of X11** `src/mwc.h:195`, leftovers, low.

   placed ("by the client"), known_app_id ("the names"), the map's reasons for reading the type and the class, frame.c's WM_NAME as Latin-1, config.c's and docs/mwmrc's Navigator, which was Firefox's X11 instance and matches nothing now, fifo.c's guess about SDL without X11, layer.c's MIN_ROOM for struts, docs/TABBED.md's X windows, and lines in README and TODO not wrapped again.

   [Fixed. No test: text.]

6. **A DISPLAY left in the user manager by an earlier X session stays there** `src/main.c:797`, session, low.

   mwc unsets DISPLAY for what it starts, but D-Bus-activated services take their environment from systemd, where mwc no longer sets DISPLAY to its own.

   [Fixed: in a real session mwc also runs `systemctl --user unset-environment DISPLAY`. No test: only in a real session, which the tests don't start.]

7. **No test of a window unmapped while it is an icon or snapped** `tests/window.sh:252`, tests, medium.

   main had it with X11 clients only (minre, halfre, quarterre). view_handle_unmap() clears minimized, xdg_unmap() snapped and maximized.

   [Fixed: window.sh hides and shows again a window that is an icon and one that is snapped; it comes back as a plain window with its title drawn. It fails without xdg_unmap()'s snap reset. Without the minimized reset it passes: the map's focus restores it anyway. Without known_title freed it passes too: the map draws the title in any case.]

8. **FUNC_CLOSE, DECOR_TITLE, DECOR_MENU and DECOR_BORDER are never taken away** `src/hints.c:68`, leftovers, low.

12. **Coverage still missing** `tests/xdgc.c:354`, tests, low.

    The pointer's focus coming back when a popup closes under a still pointer, a dialog opened later for an allDesktops window on another desktop, a dialog of a withdrawn window, a dialog that minimizes itself, and xdgc keeping its toplevel after mwc closed it (no script waits for a file after a close).

    [Left at first. Then settled: xdgc opens a dialog late also after its window is hidden (dialog_after now comes last), lets the dialog ask to be an icon (dialog_minimize_after), and leaves a window mwc closed alone, exiting when none is left. desktop.sh: a dialog an allDesktops window opens on desktop 2 is in sight there; it fails only with both paths taken out (view_on_all_desktops() for dialogs, desktop_recheck() moving the window to the current desktop). desktop.sh: shown again under its first app_id, the rules are that one's; it fails when the map keeps allDesktops. tabs.sh: a dialog that made itself an icon stays one across tab switches; it fails when dialogs_show() brings icons back. A dialog of a withdrawn window is X11 only: wlroots gives the children of an unmapped xdg toplevel to its parent (handle_parent_unmap()), so no Wayland dialog points at a withdrawn window.]

## Second round

One reviewer on 1a64a1a, two questions: whether its src/ changes keep the behaviour, and whether xdgc's changes are sound. src/: nothing found; the decoration and function bits, frame_border(), frame_title() and the order in which narrow windows drop their buttons were compared with eb81a71 for every width and set of buttons. 4 findings in xdgc, all confirmed and fixed; numbered S-0 to S-3. No tests of their own: they are in the test client, and every script using it passes.

S-0. **A dialog opened while its window is hidden has no parent** `tests/xdgc.c:815`, xdgc, low.

   wlroots keeps only a mapped parent (wlr_xdg_toplevel_set_parent()), so the "dialog of a window that isn't there" was a window of its own, and stayed one after its window came back. No script used it.

   [Fixed: dialog_after opens the dialog after all else, not while the window is hidden.]

S-1. **The late dialog could ask for its parent before that mapped** `tests/xdgc.c:564`, xdgc, low.

   open_late_dialog() lost the two roundtrips before it: with the file there already, set_parent could come before the main window had mapped, and wlroots would drop the parent.

   [Fixed: open_dialog() does the roundtrips first, for the early dialog and the late one alike.]

S-2. **What waits for a file checked that its window was alive before the wait, not after** `tests/xdgc.c:814`, xdgc, low.

   A window mwc closed during a wait (Alt+F4 on the dialog, say) was then used: a destroyed proxy, or set_app_id on NULL. The early blocks (late_app, fullscreen, grow, titles, popup, subsurface) had no check at all.

   [Fixed: each block waits, then acts only if its window is still alive().]

S-3. **unparent was ignored with dialog_after** `tests/xdgc.c:708`, xdgc, nit.

   [Fixed: open_dialog() does both. The fuzz harness also calls config_client_all_desktops() and config_client_tiles() with the rule's client again, so their matching branch is reached.]
